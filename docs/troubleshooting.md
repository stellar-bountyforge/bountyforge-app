# Troubleshooting

## bountyforge-app

### `npm run lint` prompts for ESLint setup

The repo intentionally ships without an ESLint config or dependency, so `next lint` opens an interactive prompt. Either skip linting or configure ESLint yourself. CI does **not** run lint for this reason.

### Build fails with type errors

The stack is strict TypeScript. Run `npm run build` locally — it runs the same type-check CI performs. `next-env.d.ts` and `tsconfig.json` are regenerated by Next on build; do not hand-edit them.

### App shows the wrong network

The landing card reflects `Networks.TESTNET` from `lib/stellar.ts`. Network selection is not configurable at runtime yet — see [Configuration](configuration.md).

## bountyforge-backend

### `curl /health` refuses connection

The service must be started first (`npm run dev`) and listens on `PORT` (default `8787`). Check nothing else occupies the port:

```bash
lsof -i :8787
```

### `404 {"error":"not_found"}`

Only `/health` and `/network` exist today. Any other path returns 404 by design.

## bountyforge-contracts

### `cargo test` fails with `Error(Auth, InvalidAction)`

Soroban tests must mock authorization. The tests use `env.mock_all_auths()`; if you add new tests calling auth-requiring functions, include the same call.

### `method not found in Env` for `env.accounts()`

`soroban-sdk` 28 removed `env.accounts()`. Generate addresses with:

```rust
use soroban_sdk::testutils::Address as _;
let actor = Address::generate(&env);
```

### `stellar contract build` not found

Install the Stellar CLI and the WASM target:

```bash
rustup target add wasm32v1-none
```

See the [Stellar CLI docs](https://developers.stellar.org/docs/tools/cli/stellar-cli) for installation.

## Diagnostics checklist

1. Node ≥ 20 (`node -v`), Rust stable (`rustc -V`).
2. Fresh `npm install` after pulling.
3. Env files copied from `.env.example` (see [Configuration](configuration.md)).
4. All three repos on latest `main` (`git pull --rebase`).
